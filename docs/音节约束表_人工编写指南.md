# 藏文音节合法组合约束表 · 人工编写指南

> 用途：为 TiNews 的 **ISR（非法音节率）** 与 **TiFMS 指标分量 Φ** 提供权威的合法性判据。
> 版本：v1（2026-09-15）　配套脚本：`syllable_slots_v3.py` / `syllable_rules_crosscheck.py`
> 配套数据：`syllable_tables/`（由 TiNews 语料 10,491 篇、573 万音节自动导出）

---

## 0. 核心原则：请专家「审表」，不要请专家「编表」

| 方式 | 专家工作量 | 覆盖性 | 风险 |
|---|---|---|---|
| ❌ 从零编写规则 | 2–3 天 | 依赖记忆，易漏 | 罕见组合漏编 → 合法音节被误判非法 |
| ❌ 纯语料自动导出 | 0 | 只覆盖出现过的 | 未出现的合法组合被判非法；噪声组合被判合法 |
| ✅ **预填表 + 专家审校** | **3–5 小时** | 完整（理论笛卡尔积） | 可控 |

我们已经做完两件事，专家只需做第三步：

1. **解析**：**596 万音节**（10,491 篇）按 Unicode 堆叠规则解析为 7 槽位，**96.61% 规范解析** → **3,566 个唯一槽位组合**
2. **预填**：按传统文法规则预填 **1,113 格**理论笛卡尔积，并标出每个格子在语料中的实际频次
3. **你来审**：只审「冲突项」和「未见项」，其余抽查

## 1. 找什么人

**必须满足**：
- 藏语言文学专业背景（本科或以上）
- **系统学过传统文法**：སུམ་ཅུ་པ（《三十颂》）与 རྟགས་ཀྱི་འཇུག་པ（《音势论》）
- 能读懂藏文 Unicode 编码表（我们会提供槽位与藏文术语对照）

**不满足第二条的不要用**。只做现代藏文信息处理、凭语感判断的人，会把传统文法规则写成个人习惯，且两名标注员会给出不一致的结果。

**建议配置**：
- 2 人**独立**填写（用于计算 Cohen's κ）
- 构成：1 位藏语文专业教师 + 1 位藏语言文学方向研究生
- 第 3 人仅在 κ < 0.80 时介入仲裁

**术语对照表**（写进任务书，避免沟通误差）：

| 我们的槽位名 | 藏文术语 | 英文 | 取值集合 |
|---|---|---|---|
| prefix 前加字 | སྔོན་འཇུག | prefix | ག ད བ མ འ |
| superscript 上加字 | མགོ་ཅན / ར་ལ་ས་མགོ | superscript | ར ལ ས |
| root 根字 | རྩ་བའི་ཡིག་ | root | 30 个基本辅音 |
| subscript 下加字 | འདོགས་ཅན / ཡ་ར་ལ་ཝ་འདོགས | subscript | ཡ ར ལ ཝ |
| vowel 元音 | དབྱངས་ | vowel | a aa i ii u uu e ee o oo |
| suffix 后加字 | རྗེས་འཇུག | suffix | ག ང ད ན བ མ འ ར ལ ས |
| suffix2 再后加字 | ཡང་འཇུག | suffix2 | ད ས |

## 2. 交付物清单

给专家 4 类文件（都在 `syllable_tables/`）：

| 文件 | 内容 | 专家动作 |
|---|---|---|
| `template_*.csv`（9 个） | 理论笛卡尔积 + `corpus_freq` + 空的 `verdict` 列 | **主表**，逐格填 1/0/? |
| `crosscheck_conflicts.csv` | **26 条**：我们按传统文法判「非法」、但语料里真实出现（每条附 3 个真实例子） | **优先审**：要么改规则，要么认定是噪声/异体 |
| `crosscheck_unseen.csv` | **52 条**：我们判「合法」、但语料从未出现的组合 | 确认是否真合法（防止误杀合法音节） |
| `anomaly.csv` / `particle_inventory.csv` | 无法解析的音节、粘写助词清单 | 判断边界情形，见 §5 |

**填写格式**（用 Excel 打开 CSV，UTF-8 BOM 已处理）：

```
verdict 列： 1 = 合法（藏文正字法允许）
             0 = 非法（藏文中不可能出现）
             ? = 存疑（需讨论，或属方言/音译/异体）
note  列：   填理由，尤其是与 corpus_freq 冲突时。
             建议用藏文或中文写「依据：三十颂第X颂 / 音势论 / 仅见于梵文音译 / 异体写法」
```

**不要留空**。留空格子我们无法区分「忘了」和「不确定」。

## 3. 九张表怎么填（含传统文法依据）

> 下表的「传统规则初稿」是我们按常见文法表述预填的，**必须由专家逐条校订**。
> 我们的初稿只作为起点，不是结论。

### 表 1 `template_pre_root.csv`（215 格）— 前加字 × 根字
依据：《音势论》སྔོན་འཇུག 章。
初稿（前加字 → 可接根字）：
- ག → ཅ ཉ ཏ ད ན ཙ ཛ ཞ ཟ ཡ ཤ ས
- ད → ཀ ག ང པ བ མ
- བ → ཀ ག ང ཅ ཏ ད ཙ ཛ ཞ ཟ ཤ ས ར ལ
- མ → ཁ ག ང ཆ ཇ ཐ ད ན ཚ ཛ
- འ → ཁ ག ཆ ཇ ཐ ད ཕ བ ཚ ཛ

### 表 2 `template_sup_root.csv`（129 格）— 上加字 × 根字
依据：ར་ལ་ས་མགོ 的搭配（མགོ་ཅན་གྱི་འཇུག་པ）。
初稿：
- ར་མགོ → ཀ ག ང ཅ ཇ ཉ ཏ ད ན བ མ ཙ ཛ
- ལ་མགོ → ཀ ག ང ཅ ཇ ཏ ད པ བ མ ཧ
- ས་མགོ → ཀ ག ང ཉ ཏ ད ན པ བ མ ཙ ཛ

### 表 3 `template_root_sub.csv`（172 格）— 根字 × 下加字
依据：ཡ་ར་ལ་ཝ་འདོགས 的搭配。
初稿（下加字 → 可接根字）：
- ཡ་འདོགས → ཀ ཁ ག པ ཕ བ མ
- ར་འདོགས → ཀ ཁ ག ང ཏ ཐ ད ན པ ཕ བ མ ས ཧ
- ལ་འདོགས → ཀ ག ང ད བ མ ཧ ཟ
- ཝ་འདོགས → ཀ ཁ ག ང ཅ ཆ ཇ ཉ ཏ ཐ ད ན ཙ ཚ ཛ ཞ ཟ འ ཡ ར ལ ཤ ས ཧ

### 表 4 `template_suf_suf2.csv`（20 格）— 后加字 × 再后加字
依据：《三十颂》ཡང་འཇུག 只有 ད 与 ས 两个。
初稿：**ད 只接 ན ར ལ 之后；ས 只接 ག ང བ མ 之后**。
这张表最小，请专家**务必逐格确认**——它对 ISR 影响最直接。

### 表 5 `template_pre_sup.csv`（15 格）— 前加字 × 上加字
例：བསྒྲུབས = 前加 བ + 上加 ས + 根 ག。请确认哪些 (前加字, 上加字) 对可共存。

### 表 6–7 `template_pre_sub.csv` / `sup_sub.csv`（20 / 12 格）
前加字/上加字 与 下加字 的共现限制。

### 表 8 `template_root_suf.csv`（430 格）— 根字 × 后加字
**格数最多的一张**。传统文法中后加字搭配相对自由，但并非无限制（如 འ 作后加字只接特定根字）。
建议策略：先填"确定非法"的格子，其余按语料频次判断——`corpus_freq` 高却判非法的，必是填错。

### 表 9 `template_vow_suf.csv`（100 格）— 元音 × 后加字
用于检测"某元音后不能接某后加字"的约束。

## 4. 三条硬性填写纪律

1. **判"非法"要给出理由**。特别是 `corpus_freq > 100` 却判非法的格子——要么规则初稿错了，要么语料里有异体/音译，必须二选一写在 note 里。
2. **区分「标准藏文不合法」与「仅见于梵文音译」**。后者填 `?`，不要填 0。梵文音译（如 ཊ ཌ ཎ དྷ བྷ ཥ 参与的音节）在现代藏文新闻中真实存在，判非法会系统性抬高 ISR。
3. **不要凭语感**。若两位专家对同一格判断不同，以传统文法典籍为准；典籍无明确记载的，填 `?` 并在 note 注明。

## 5. 六类边界情形（必须请专家明确表态）

这些是自动解析无法自行决定的，我们在语料里都实际观测到了：

| # | 情形 | 语料中的真实例子 | 需专家回答 |
|---|---|---|---|
| 1 | **梵文音译字母**：ཊ ཌ ཎ དྷ བྷ ཥ 及其堆叠 | 语料 root 槽位出现 36 种取值，含这 6 个梵文字母 | 是否计入合法音节？堆叠形式（如 བྷ）是否合法？ |
| 2 | **粘写格助词**：འི འུ འོ འེ འང འམ 等粘在前音节上 | 共 31 种、**26 万次，占 4.38%**；`པོའི`(པོ+འི)、`ཧྲུའུ`、`བའང` | 我们已自动剥离再判音节，此处理是否正确？还有哪些粘写形式？ |
| 3 | **双重下加字** | 观测到 sub=`རཡ`（如 སྒྲྱ 类） | ར+ཡ 双重下加在标准藏文中是否存在？ |
| 4 | **上加字/下加字同形歧义** | སྲ 既可解为「上加ས+根ར」也可解为「根ས+下加ར」，**占 1.40%**（8.07 万次） | 是否有消歧规则？还是两种解析都判合法？ |
| 5 | **异体写法** | 上加字用基本形 vs 根字用 subjoined，两种 Unicode 表示 | 两种是否等价？ISR 计算是否应归一化后再判？ |
| 6 | **数字/标点/缩写** | 藏文数字 ༠-༩、། ༎、缩写音节 | 是否一律排除在 ISR 分母之外？ |

## 6. 质量检验（我们来做，但专家需配合）

1. **双人一致性**：两名专家独立填写，计算 Cohen's κ。
   - κ ≥ 0.80：直接采用
   - 0.60 ≤ κ < 0.80：分歧格由第 3 人仲裁
   - κ < 0.60：任务书有问题，需重新培训后重填
2. **语料回测**：用最终规则表重跑 573 万音节，统计 ISR。
   - 若 ISR > 5%：说明规则过严（合法音节被误杀），需复查冲突清单
   - 若 ISR < 0.1%：说明规则过松（约束表没起作用），需检查是否大量格子填了 1
3. **抽样人工复核**：随机抽 200 个被判非法的音节，请第 3 位母语者确认。

## 9. 常见问题（提前回答专家会问的）

**Q：为什么不直接用藏文词典/输入法词库？**
A：ISR 要判的是**音节**合法性，不是词。词典收录的是词，且覆盖率受限于词典规模；而音节构成是封闭的语法规则，理论上可穷尽。两者不在一个层次。

**Q：我已经给了语料频次，直接按频次判不行吗？**
A：不行。语料里没出现的组合不等于非法（否则 ISR 会系统性偏高，把模型生成的罕见合法音节误判为错误）；语料里出现的也不一定合法（语料本身有 OCR/转写噪声）。所以需要人的语法判断来"兜住"两端。

**Q：我填的规则会被怎么用？**
A：编译成一个确定性的音节合法性判定器，用于计算生成文本中非法音节的比例（ISR）。它是 TiFMS 指标的一个分量，**不会被用来训练任何模型**，也不会改变语料。

**Q：填错了会怎样？**
A：规则过严 → ISR 虚高，论文结论偏向"模型生成质量差"；规则过松 → ISR 虚低，指标失去区分力。所以 §6 的回测是必须的，我们会把回测结果反馈给专家复核一轮。
